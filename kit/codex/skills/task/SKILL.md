---
name: task
description: Создать или продолжить задачу AI Workflow Kit по ID, провести её через спеку, реализацию, ревью и приёмку.
---

Вызов: `$task new "заголовок"` или `$task VC-001`.

1. При продолжении прочитай `tasks/<ID>.md`, особенно «Как продолжить», и проверь фактическое состояние git. Для новой задачи обнови доску командой `node .codex/workflow/board.js`, возьми следующий свободный ID и скопируй `tasks/_template.md`, не перезаписывая существующую задачу. Запиши запрос, размер и `status: discuss`.
2. S: цель, границы, критерии и проверка в задаче. M/L: изучи продуктовые риски, альтернативы, контракты и зоны; для UI добавь дизайн-критерии. Используй доступных субагентов только если делегирование разрешено; иначе выполни анализ сам.
3. Для M/L примени `$spec <ID>`: реализация начинается после явного утверждения спеки. Для бага используй `$debug <ID>`.
4. Зафиксируй исходный коммит, план и зоны. Для M/L проверь утверждённый статус и `node .codex/workflow/spec.js check <ID>`. Передай исполнителю путь к спеке, зону, границы файлов, проверку и запрет коммитить/пушить без разрешения. Если работаешь один, выполни тот же план самостоятельно. Статус задачи — `in_progress`.
5. Разбери отчёт: DONE → ревью; DONE_WITH_CONCERNS → сначала закрой сомнения о корректности; NEEDS_CONTEXT → добавь контекст; BLOCKED → измени подход, не повторяй тот же бриф без изменений.
6. В `review` проверь дифф от сохранённой базы и соответствие спеке. Независимый ревьюер предпочтителен, если доступен; иначе явно укажи самопроверку. По каждому замечанию запиши принятие или мотивированное отклонение. Повторно проверяй исправления. После трёх неудачных раундов пересмотри подход; после пяти с блокерами обратись к пользователю.
7. В `acceptance` запусти проверки, сверь критерии и запиши свидетельства в задачу. Только затем `done` и разрешённый локальный коммит `type(<ID>): описание`, включающий задачу, доску и спеку. Отчёт пользователю: изменения, результаты проверок, ограничения и решения без его участия.

После каждого значимого шага обновляй «Журнал», «Решения», «Как продолжить» и `node .codex/workflow/board.js`. Не позволяй нескольким исполнителям одновременно редактировать файл задачи.

При разрешённом делегировании используй проектные роли через `spawn_agent.agent_type`: explore-opus для исследования, product-critic и arch-critic до спеки M/L, ui-designer для UI после продуктовой критики, impl-sonnet для механики по образцу, impl-opus для нетривиальной реализации, отдельный review-opus для независимого ревью. Модель и усилие берутся из `.codex/agents/*.toml` (GPT-6 Sol); не заменяй их случайными моделями.
