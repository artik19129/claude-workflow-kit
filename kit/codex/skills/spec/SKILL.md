---
name: spec
description: Создать, проверить или пересогласовать спеку задачи M/L перед реализацией.
---

Вызов: $spec <ID>.

1. Прочитай задачу, релевантную память и текущие контракты. Для M/L проверь продуктовые и архитектурные риски; привлеки отдельного критика, если неоднозначность/риск оправдывает запуск.
2. Создай спеку: node .codex/workflow/spec.js new <ID> <slug>, либо открой существующую. Заполни цель, не делаем, поведение, контракты, ограничения, зоны, тесты и критерии. Зоны не пересекаются по файлам, общие ресурсы проверки указаны явно.
3. Ожидаемые результаты тестов выводи из требований/эталона, а не из будущей реализации. Каждому риску — достаточная проверка, без инфраструктуры «на всякий случай». Спорные расширения покажи отдельно.
4. node .codex/workflow/spec.js check <ID>. Покажи пользователю результат и существенные решения. До явного утверждения — draft. После согласия: node .codex/workflow/spec.js approve <ID>. Наличие статуса не подтверждает само по себе, что согласие действительно получено.
5. В брифы — Workflow-Task: <ID>, путь к спеке и зона. Изменение требований после согласования: draft → конкретный diff требований → новое утверждение. Ошибку предположения внутри объёма исправляй с записью доказательства, не раздувая задачу.
