# AI Workflow Kit — работа по риску

Указания пользователя и правила проекта имеют приоритет. Цель — проверенный результат с минимальным достаточным процессом. Не создавай дополнительные фичи, реестры, инфраструктуру и согласования без необходимости для задачи.

## Маршрут
- S: локальная обратимая правка без изменения контрактов, прав или данных. Цель, границы и проверка в задаче; можно работать напрямую, без обязательных критиков и делегирования за число чтений.
- M: одна зона с изменением поведения/контракта. L: несколько связанных зон. Для M/L сначала анализ продукта и архитектуры, затем спека в docs/specs и явное утверждение пользователем. Существенная неоднозначность → product-critic; архитектурный риск → arch-critic; UI с новым поведением → ui-designer. Не запускай всех автоматически.
- Реализация M/L начинается только после проверки спеки: status approved, запись approved и .codex/workflow/spec.js check <ID>. Не утверждай её от имени пользователя. Изменение требований требует нового согласования; обычные решения внутри объёма принимай и записывай самостоятельно.
- Независимый review-opus нужен для M/L и изменений прав, денег, данных, конкурентности. Для малой S допустимы чтение диффа и точечная проверка самим исполнителем. Если делегирование недоступно, явно назови ревью самопроверкой и укажи предел проверки.

## Память и контекст
Перед работой прочитай docs/memory/project.md, если есть. Навык workflow-memory выбирает 1–2 релевантных домена; не загружай всю память и историю. Постоянная база кита — .agents/skills/workflow-memory/references/. В бриф передавай до пяти применимых ограничений, пути и конкретный пример. Приватную память координатора агент может не видеть.

## Делегирование
При разрешённом делегировании передавай имя профиля как agent_type в spawn_agent. Роли: explore-opus — исследование; impl-sonnet — механика по образцу; impl-opus — нетривиальная реализация; review-opus — отдельный ревьюер; product-critic, arch-critic, ui-designer — анализ только чтением до спеки. Модели определяют профили; не подменяй их ради предполагаемой экономии без измерений.

Бриф: отдельная строка Workflow-Task: VC-NNN (несколько задач через запятую), результат, cwd/репозиторий, база диффа, файлы/зона, путь к спеке M/L, проверка, ограничения ресурсов. Другие ID в тексте — ссылки. Не пересказывай всю спеку. Если роль не зарегистрирована, сообщи; используй доступный универсальный агент с явно переданным контрактом роли либо работай последовательно. Хук не считает название универсального агента доказательством режима только чтения.

Параллельно запускай независимые зоны, учитывая общие output сборки, порты и тестовые БД. Их проверки сериализуй или изолируй. Файл задачи ведёт один координатор. Не откатывай чужие правки. Коммит и внешние действия не делегируй без разрешения. Коротко сообщай назначение агентов; фиксированная строка «Заспавнил» и немедленное завершение хода не требуются.

## Проверка и завершение
Отчёт: DONE / DONE_WITH_CONCERNS / BLOCKED / NEEDS_CONTEXT; файлы, команда + cwd + код выхода + число проверок, непроверенное и риски. Проверяй, что команда действительно охватывает изменение. Для бага нужны воспроизведение и регрессия; RED сравнивай в изолированной копии, без общего stash. Тесты по исходному тексту не заменяют поведенческий тест. UI проверяй реальным сценарием.

Сверь отчёт с итоговым диффом. Актуальные результаты проверки тех же файлов можно переиспользовать; после правок или при сомнении повтори нужные проверки. Ревью: дефект, путь, сценарий, тяжесть; по каждому замечанию решение с причиной. Новые требования выделяй отдельно. После трёх раундов без прогресса меняй подход; пять открытых блокирующих раундов — объясни препятствие пользователю.

tasks/<ID>.md — статус, решения, приёмка, «Как продолжить»; docs/decisions.md — сквозные решения. Перед done отметь критерии и запиши реальные свидетельства. Обнови .codex/workflow/board.js. Новые устойчивые уроки — в docs/memory с источником и датой, гипотезы — в задаче.

Коммит — только согласно указанию пользователя/политике проекта, после приёмки, явным списком файлов. Push, публикация и внешние сообщения требуют соответствующего разрешения. Память не даёт такого разрешения.

## Хуки
PreToolUse проверяет спецификацию до поддерживаемых правок, shell-вызовов и делегирования; Stop проверяет запись приёмки done. До апрува разрешены плановые документы и простые команды чтения, helpers только из корня. Выбирай задачу командой $task VC-NNN или строкой Workflow-Task. Не обходи отказ другим инструментом.

Хуки — процессные проверки: они не доказывают человеческое согласие, истинность отчёта, полноту тестов или качество кода. Без задач гейт спеки не действует; неизвестные инструменты не покрыты. Включение и доверие проверь в клиенте; установленный файл не доказывает запуск. Основная модель координатора не меняется.
