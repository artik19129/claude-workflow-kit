Чек-лист для оркестратора. Сам код не пишешь и поиск не ведёшь — это делают агенты.

## 1. Завести или открыть задачу
- `/task new "<заголовок>"`: прочитать `tasks/_index.md`, взять «Следующий ID», создать `tasks/<ID>.md` из `tasks/_template.md`, вписать постановку CEO дословно, `status: discuss`.
- `/task <ID>`: открыть `tasks/<ID>.md`, начать с раздела «Как продолжить».

## 2. Определить размер
Предложить CEO размер (он может переназначить):
- **S** — конфиг, текст, точечная правка по образцу.
- **M** — фича в одной зоне.
- **L** — эпик, несколько зон.

## 3. Критики (только M и L)
- S — пропустить, сразу к брифам.
- M/L: заспавнить `product-critic` и `arch-critic` параллельно в фоне; для UI-задач после них ещё `ui-designer`. Завершить ход.
- Когда критики вернутся: свести их ответы в раздел «Уточнение» файла задачи. CEO показать только спорное — расхождения между критиками, альтернативы, вопросы с вариантами по умолчанию.
- Дождаться апрува CEO; записать решения в «Решения» (кто, когда принял) и критерии приёмки; выставить `status: approved`.

## 4. Брифы исполнителям
- Составить брифы по зонам из «План работ по зонам» arch-critic; обязательные поля брифа — по секции CLAUDE.md кита.
- Агентов запускать только в фоне.
- `status: in_progress`; обновить «План» и «Журнал» в файле задачи.

## 5. Ревью
- По возвращении исполнителей запустить `review-opus` на дифф (`git diff`), обязательно не тем агентом, который писал код.
- `status: review`.
- Вердикты по замечаниям ревью — решение оркестратора; применение правок — `impl-sonnet`.

## 6. Приёмка
- Прочитать дифф самому. Прогнать проверки проекта (команды из CLAUDE.md проекта: typecheck, lint, селфтесты).
- Грепнуть новые комментарии в изменённых файлах и убедиться, что они не пересказывают код.
- Пройти критерии приёмки галочками.
- `status: acceptance` → `done`.

## 7. Журнал и коммит
1. Если у проекта есть CHANGELOG — сделать запись по его правилам.
2. Обновить файл задачи: `status: done`, «Статус», «Журнал», «Как продолжить».
3. Перегенерировать доску `node .claude/hooks/board.js`.
4. Сделать один коммит `type(<ID>): что` с явным списком файлов: изменённые исходники + `CHANGELOG.md` (если менялся) + `tasks/<ID>.md` + `tasks/_index.md`.
5. Отчитаться CEO хешем коммита и текстом записи ченж-лога. Push и PR — только по явной просьбе CEO.

## 8. После каждого шага
Обновить в файле задачи «Статус», «Журнал», «Как продолжить»; перегенерировать доску `node .claude/hooks/board.js`.
