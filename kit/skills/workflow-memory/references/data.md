# Данные и изоляция тестов

- Проверяй SQL по реальной схеме и миграциям, включая связующие таблицы, nullability и права. Чтение текста запроса не подтверждает существование столбцов.
- Smoke/HTTP-тесты выполняй на отдельной тестовой БД с тестовыми данными. Запуск приложения может выполнить миграции и фоновые записи даже при чтении endpoint. Наличие локального файла не означает, что данные одноразовые.
- Если нужна копия SQLite в WAL-режиме, используй согласованный backup/snapshot либо остановленный источник. Простое копирование основного файла может потерять committed данные из WAL. Не включай рабочие данные в репозиторий или отчёт.
- Фикстура должна удовлетворять схеме и активировать сценарий. `INSERT OR IGNORE` способен молча не вставить строку; проверь количество вставок, связи и предусловия JOIN.
- Сбрасывай изменяемую фикстуру между тестами. Порядок тестов не должен компенсировать зависимость от чужих записей. Закрывай соединения; убирай только принадлежащие тесту файлы, включая его WAL/SHM и копии данных, в finally.
- Для проверки прав используй разрешённый и запрещённый сценарии, а также чужой объект. Проверка одной административной роли не доказывает разграничение доступа.

Основание: vualya-crm, память `http-smoke-on-db-copy`, `verify-db-code-against-schema`, `nestjs-api-rewrite-gotchas`; employee-portal, `docs/access-rules.md`. Перенесены общие инварианты, не пути/данные проектов. Пересмотр 2026-10-15.
