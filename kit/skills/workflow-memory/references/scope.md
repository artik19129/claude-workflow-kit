# Объём задачи и цена процесса

- Бриф содержит результат, ограничения, нужные файлы/контракт, проверку и формат отчёта. Титул «senior» не заменяет этих данных. Передавай существенные проектные правила явно; приватная память координатора агенту не гарантирована.
- «Убрать механизм» означает проверить и его копии, а не перенести ту же таблицу или логику в тестовый каталог. Сохраняемую часть обоснуй относительно запроса; не маскируй неполное удаление переименованием.
- Ревью оценивает результат в рамках задачи. Каждый запрос на инфраструктуру, новый реестр, CI или общий рефакторинг проверяй: нужен ли он для заявленного результата? Нужные поведенческие тесты входят в реализацию; отдельная платформа тестов автоматически не входит.
- У замечания должен быть сценарий дефекта и место в коде. Предпочтение стиля не блокирует задачу, если стиль не нарушает правила проекта. Принятие/отклонение записывай коротко с причиной.
- Малую задачу можно выполнить напрямую. Для M/L всё равно нужен анализ продукта и архитектуры; отдельных критиков запускай при существенной неоднозначности/риске. Независимое ревью сохраняй для контрактов, данных, прав, денег, конкурентности и M/L.
- После двух одинаковых неудач измени гипотезу/контекст; после третьего раунда без прогресса пересмотри подход. Новый агент с тем же пустым брифом не снижает риск.

Основание: employee-portal, `agent-briefing-standard`, `remove-means-remove`, `scope-beyond-request`; vualya-crm, `critic-agents-not-registered`. Пересмотр 2026-10-15. Частное требование согласовывать каждую техническую мелочь не перенесено: обычные решения внутри задачи остаются автономными.
