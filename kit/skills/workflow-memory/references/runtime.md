# Окружение и фактическое исполнение

- Проверяй действующий runtime, а не наличие записи в конфиге. Например, ограничения контейнера должны наблюдаться внутри контейнера; успешное принятие флага само по себе не доказывает лимит. Способ проверки зависит от ядра, runtime и платформы.
- До старта сервера проверь порт и рабочий каталог. После остановки проверь освобождение порта. Завершай только процесс, принадлежность которого подтверждена; PID оболочки может не совпадать с PID дочернего сервера.
- Пути к runtime-файлам проверяй в собранном артефакте. Компилятор может изменить структуру output; успешная сборка не подтверждает правильность entrypoint, конфигов и статических ресурсов.
- При проблеме запуска инструмента различай ошибку приложения и оболочки. Не повторяй неизменный падающий вызов бесконечно; проверь путь, cwd и код выхода, затем используй поддерживаемый способ запуска.
- Не копируй серверные адреса, UID, секреты и частные команды развёртывания из другого проекта. Бери значения из документации текущего окружения. Проверка не даёт разрешения на деплой.

Основание: foowe-sandbox, `deploy/README.md` и `server-execution-plane` (обезличено); patchbay, `patchbay-parallel-acceptance`; vualya-crm, `nestjs-api-rewrite-gotchas`. Пересмотр 2026-10-15.
