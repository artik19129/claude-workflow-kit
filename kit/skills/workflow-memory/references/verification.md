# Проверка, которая действительно проверяет

- Успешный exit code недостаточен. Убедись, что команда включает нужные файлы и выполнила тесты. В TypeScript конфигурация с `files: []` и `references` может требовать build mode; используй проверенный скрипт проекта, не придумывай аналог по имени папки.
- Тест должен достигать изменённой ветки. Зафиксируй предусловие: есть строки после JOIN, активная кнопка, валидная роль, нужное событие. Пустая выборка или пустое поле способны дать ложный успех.
- Ожидаемое поведение бери из согласованного контракта, предыдущей реализации или внешнего эталона. Тест нового кода с ожиданиями из того же кода не доказывает совместимость. При переносе сравни обе реализации на одинаковых входах, включая коды и тело ошибок.
- Bootstrap теста может пропускать middleware, guards, validation и префикс реального сервера. Отдельно проверь границу, которую меняет задача. Успех теста репозитория БД не доказывает HTTP-контракт.
- Для бага добейся RED по нужной причине и GREEN после правки. Не ломай общее рабочее дерево для повторной проверки: изолированная копия или отдельное дерево, куда перенесён только нужный дифф. Не делай общий stash чужих правок.
- Отчёт включает команду, cwd, код, число реально выполненных/пропущенных проверок и состояние проверяемых файлов. Повторный полный прогон нужен после новых изменений или при сомнении в артефакте; достоверный актуальный вывод можно переиспользовать. Оркестратор проверяет соответствие вывода итоговому диффу.

Основание: patchbay, память `patchbay-parallel-acceptance` и текущий desktop tsconfig; vualya-crm, `verify-db-code-against-schema`, `nestjs-api-rewrite-gotchas` (исторический опыт, не описание текущего стека). Проверено 2026-10-15.
