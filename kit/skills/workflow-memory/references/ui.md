# UI и доступность сценария

- Начинай с существующих компонентов и токенов. Если есть несколько тем/брендов, проверь затронутую функцию в каждом; не копируй конкретные палитры и правила проекта в универсальный кит.
- Проверяй реальное взаимодействие в браузере: desktop/mobile, пусто, загрузка, ошибка, нет доступа. Сборка и скриншот стартового экрана не заменяют сценарий.
- Подготовь валидные тестовые данные: даты, роли, открытый статус, связи. Недоступная кнопка не доказывает, что её обработчик работает. Используй тестовое окружение и убирай созданные данные.
- Для SSR/CMS/cache проверь отдельно успешный ответ, отсутствие объекта и недоступность источника. Временный сбой не должен превращаться в долгоживущий закешированный 404. Страница, собранная без backend, требует проверки после старта реального окружения.
- После изменения процесса/зависимостей убедись, что браузер обращается к актуальной сборке. Ошибки устаревшего dev-кеша сначала воспроизведи после штатного перезапуска своего процесса, а не исправляй бизнес-логику наугад.

Основание: employee-portal, `design-system-rules`; vualya-crm, `preview-visual-acceptance-recipe`; vualya-site, README «Кэш страниц», `test/pages.test.ts`. Пересмотр 2026-10-15.
