# Параллельная работа

- Разделяй не только исходники, но и ресурсы: output сборки, dev-сервер, порт, тестовая БД, generated файлы. Два агента в разных файлах могут испортить один общий e2e-прогон пересборкой.
- В брифе укажи cwd/репозиторий, базовый коммит, владельца файлов и эксклюзивных ресурсов. При общих outputs сборки и e2e идут по очереди; при изолированных — параллельно.
- Файлы задачи и итоговые решения ведёт один координатор. Агенты возвращают отчёт, не переписывают общий журнал одновременно.
- В общем дереве не используй stash/reset/checkout для временного удаления правки. Для сравнительной проверки создай отдельную копию/дерево, включив только нужные изменения. Не принимай весь чужой diff за свой результат.
- Потерянный отчёт не означает отсутствие изменений. Проверь статус агента, diff и ресурсы; продолжи того же агента с конкретным вопросом, прежде чем запускать дубль.
- Параллелизм оправдан независимыми зонами. Последовательные зависимости и небольшие S-задачи обычно дешевле вести без отдельного оркестрационного дерева.

Основание: patchbay, `patchbay-parallel-acceptance`, цикл нескольких S-задач 2026-10-13; employee-portal, `agent-briefing-standard`. Пересмотр 2026-10-15.
