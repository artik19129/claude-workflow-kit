---
name: debug
description: Установить причину бага по свидетельствам, исправить и проверить регрессию.
---

Вызов: /debug <ID>.

1. Запиши точный симптом, окружение, входные данные, роль, шаги и ожидаемый результат в tasks/<ID>.md. Прочитай релевантные домены workflow-memory (обычно verification и data/runtime).
2. Найди границу возникновения ошибки: вход → обработка → выход, факты с путями/строками. Проверь недавний diff и работающий аналог. Для сложной трассировки используй explore-opus; короткую диагностику можно сделать напрямую.
3. Неподтверждённая гипотеза — повод собрать свидетельство, не массово менять код. Минимальный воспроизводящий тест должен падать по нужной причине. Если автоматизация неуместна, запиши воспроизводимый ручной сценарий.
4. S без изменения контракта можно исправить напрямую; M/L требуют спеки. Исправь причину, прогони регрессию и нужные проверки потребителей. Не расширяй задачу попутными улучшениями.
5. Для RED-сравнения используй отдельную копию/дерево с нужным диффом. Общий git stash, reset и перезапись чужих правок запрещены. Проверь, что тест достиг нужной ветки, а не прошёл на пустых данных.
6. Приёмка и ревью — по /task. После трёх попыток без прогресса пересмотри гипотезу/архитектуру. Установленную причину, проверку и применимость урока сохрани через workflow-memory.
