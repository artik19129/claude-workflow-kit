Чек-лист для оркестратора. Спека — единственный источник требований для исполнителей и ревьюера; бриф на неё ссылается, а не пересказывает. Пишет её оркестратор: это проектирование, не код.

## 1. Материал
Прочитать `tasks/<ID>.md`: постановку, «Уточнение» (product-critic, arch-critic, ui-designer), «Решения». Если критики не запускались — сначала шаг 3 из `/task`. Если ответы критиков расходятся и CEO ещё не решил — спека не пишется: вопрос CEO с вариантом по умолчанию.

## 2. Создать файл
`node .claude/hooks/spec.js new <ID> <slug>` — slug латиницей через дефис (`export-csv`). Команда создаёт `docs/specs/<ID>-<slug>.md` из `docs/specs/_template.md` и прописывает путь в поле `spec:` файла задачи. Спека уже есть и нужна правка — открыть её, поставить `status: draft`, дальше с шага 3.

## 3. Заполнить разделы
Каждый раздел — конкретика вместо подсказки из шаблона:
- **Цель** — одна фраза: что станет возможным и для кого.
- **Трактовка и допущения** — из «Как понял задачу» критиков: выбранная трактовка; отвергнутые — одной строкой почему.
- **Не делаем** — из «Вне задачи» product-critic и YAGNI по каждому пункту постановки. Раздел непустой всегда.
- **Поведение** — по ролям и сценариям. Пустое состояние, ошибка, нет доступа, повтор действия, рестарт — каждое либо описано, либо явно «не применимо».
- **Контракты** — из «Контракты и данные» arch-critic: точные имена, типы, ключи, миграции. То, что исполнители разных зон должны видеть одинаково, живёт только здесь.
- **Ограничения** — из «Ограничения» arch-critic и CLAUDE.md проекта: версии, лимиты, терминология, язык текстов. Ревьюер сверяет с этим списком дословно.
- **Что меняется / что не меняется** — таблица; «не меняется» защищает от расползания правок.
- **Зоны работ** — из «План работ по зонам» arch-critic: файлы, что зона потребляет и производит (сигнатуры), исполнитель (impl-sonnet / impl-opus), команда проверки. Зоны не пересекаются по файлам; порядок сверху вниз.
- **Тесты** — какой тест доказывает какой критерий: файл, сценарий, ожидаемый результат. Автотестов нет — почему и чем заменяются.
- **Критерии приёмки** — из product-critic, поведением пользователя, галочками.
- **Открытые вопросы** — вопрос, вариант по умолчанию, кто решает. Перед апрувом каждый пункт закрыт пометкой «решено: …» или раздел пуст.

## 4. Самопроверка
1. `node .claude/hooks/spec.js check <ID>` — пустые разделы, незаменённый текст шаблона, заглушки (TBD, TODO, «уточнить»), открытые вопросы. Чинить до нуля замечаний.
2. Прочитать спеку целиком свежим взглядом: разделы не противоречат друг другу (контракт в «Контрактах» совпадает с «Зонами» и «Тестами»); одна спека — одна задача (несколько независимых подсистем → L и разбиение на M); ни одно требование нельзя прочитать двумя способами — если можно, выбрать одно и записать.
3. Чинить сразу; повторный круг не нужен.

## 5. Апрув CEO
Показать CEO путь к спеке и только спорное: где трактовка выбрана без него, отвергнутые альтернативы, цена ограничений. Ждать явного «ок». Правки CEO — в спеку, снова `check`.
После «ок»: `node .claude/hooks/spec.js approve <ID>` (status: approved, дата, кто), в файле задачи `status: approved`, в «Решения» — «спека утверждена CEO, дата».

## 6. Изменение после апрува
Утверждённый текст меняется только через CEO: `status: draft` в спеке → правка → `check` → апрув → `approve`. Работающих исполнителей уведомить через SendMessage (строка «Продолжаю: …») или перезапустить с новым брифом. Двусмысленность, которую можно снять без изменения текста, — решение оркестратора в «Решения» с пометкой «оркестратор»; спеку не трогать.

## Красные флаги
| Мысль | Реальность |
|---|---|
| «Задача понятная, спека на пять строк» | Пять строк — тоже спека. Хук не пропустит M/L без неё. |
| «Скопирую ответ arch-critic целиком» | Ответ критика — материал с альтернативами; спека — решение без них. |
| «Открытый вопрос оставлю, исполнитель разберётся» | Исполнитель решит по-своему в каждой зоне. Закрыть до апрува. |
| «CEO занят, утвержу от его имени» | approve — только после явного «ок» CEO. Пока его нет — status: discuss. |
| «Спека утверждена, но по ходу лучше сделать иначе» | Иначе = новая версия через CEO. Молча — нельзя. |
