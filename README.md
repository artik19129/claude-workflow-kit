# AI Workflow Kit — Claude Code и Codex

Переносимый набор проектных инструкций, семи ролей агентов, навыков, тематической памяти, задач, спек и хуков. Node.js ≥18, без npm-зависимостей. Имя пакета `claude-workflow-kit` сохранено для совместимости.

## Версия 1.5

- Общая политика хуков для обоих клиентов: проверка **до действия**, а не после запуска исполнителя.
- Память по семи доменам загружается по риску задачи; особенности проекта хранятся отдельно.
- Малая S-задача может выполняться напрямую. Для M/L сохраняются спека, её утверждение и независимое ревью; отдельные критики привлекаются по необходимости.
- Вместо квоты чтений и обязательной строки «Заспавнил» — конкретные критерии качества и явная привязка брифа `Workflow-Task`.
- `status` обнаруживает подмену условий, дубли и асинхронный режим хуков кита; `update` восстанавливает их определения.

Обоснование решений, источники уроков и границы проверки: [аудит 2026-10-15](docs/kit-improvement-audit-2026-10-15.md). Результаты проверок: [отчёт](docs/verification-2026-10-15.md).

## Установка и обновление

```sh
node install.js install <проект> --target both
node install.js update <проект> --target both
node install.js status <проект> --target both
node install.js uninstall <проект> --target codex
```

Без `--target` выбирается `claude`. Значения: `claude`, `codex`, `both`; при каждом вызове указывайте нужную цель. Можно добавить второй клиент к уже установленному первому. Установщик работает с указанным проектом, не с глобальным профилем.

| Флаг | Действие |
| --- | --- |
| `--dry-run` | Показывает изменения без записи |
| `--node <путь>` | Исполняемый Node для хуков Claude; выбор сохраняется в kit.json |
| `--no-design-skill` | Не устанавливать необязательный приватный emil-design-eng |
| `--design-skill` | Установить emil-design-eng при наличии исходников; выбор запоминается |

Для Codex нужен Node в PATH. Claude получает exec-форму `command` + `args`, без shell-перекодирования путей. При установке Claude отсутствующий emil-design-eng может копироваться из локального кэша плагинов; Codex использует только уже имеющуюся копию в ките. Этот навык не публикуется. `ui-ux-pro-max` включён в кит с собственной MIT-лицензией и поисковой базой; дизайнер использует его только когда не хватает проектных материалов.

### Расположение файлов

| Назначение | Claude | Codex |
| --- | --- | --- |
| Инструкции | управляемый блок CLAUDE.md | управляемый блок AGENTS.md |
| Роли | .claude/agents/*.md | .codex/agents/*.toml |
| Навыки и базовая память | .claude/skills/ | .agents/skills/ |
| Скрипты | .claude/hooks/ | .codex/workflow/ |
| Хуки | .claude/settings.json | .codex/hooks.json |
| Состояние установки | .claude/kit.json | .codex/workflow-kit.json |
| Задачи, спеки, локальная память | tasks/, docs/specs/, docs/memory/, docs/decisions.md | те же общие файлы |

`update` перезаписывает файлы кита и его блок инструкций. Проектные шаблоны создаются только при отсутствии; существующие задачи, спеки и память не перезаписываются. Не редактируйте поставляемую базу памяти: дополнения живут в `docs/memory/`.

Codex отказывает до записи при конфликте нового файла с пользовательским и проверяет список принадлежащих киту файлов в манифесте. Claude использует набор путей исходного кита: перед первой установкой проверьте совпадающие имена собственных агентов/навыков, они могут быть перезаписаны. Чужие хуки, поля настроек, текст вне управляемого блока сохраняются. Удаление кита сохраняет проектные документы; для файлов самого кита поведение соответствует манифесту Codex или набору исходников Claude. Удалённый из исходников старый файл Claude автоматически не вычищается.

Claude обновляет собственный блок `.gitignore` и убирает общие исключения `.claude`, которые скрывают его файлы. Codex `.gitignore` не меняет: при необходимости разрешите `.codex/agents/`, `.codex/workflow/`, `.codex/hooks.json`, `.codex/workflow-kit.json`, `.agents/skills/`. Проверяйте `git status` перед коммитом.

После обновления начните новую сессию. В Codex проект должен быть доверенным, а определения хуков проверены и разрешены через `/hooks`; изменения могут требовать повторного доверия. `AGENTS.override.md` имеет приоритет над AGENTS.md, установщик предупреждает о нём. В Claude проверьте `/hooks` и отсутствие отключающих настроек. `status` проверяет файлы и конфигурацию, **не доказывает исполнение клиентом**. Глобальные настройки и модель координатора не меняются.

## Работа по риску

| Размер | Процесс |
| --- | --- |
| S | Локальная обратимая правка без изменения контрактов, прав и данных. Цель, критерии, достаточная проверка; можно напрямую |
| M | Одна зона: продуктовый/архитектурный анализ, спека, утверждение, реализация, независимое ревью, приёмка |
| L | Несколько зон: общий контракт, спека, утверждение, независимые задания, интеграционная проверка и ревью |

Для M/L анализ обязателен, но запуск двух отдельных критиков не обязателен при ясных требованиях и низкой неопределённости. Product-critic полезен при продуктовой неоднозначности, arch-critic — при архитектурном риске, ui-designer — для нового поведения UI. Модели ревью не удешевляются ради предполагаемой экономии.

Бриф исполнителя или ревьюера:

```text
Workflow-Task: VC-001
Результат: ...
Репозиторий/cwd: ...
База диффа: ...
Спека: docs/specs/VC-001-export-csv.md
Зона/файлы и общие ресурсы: ...
Проверка результата: ...
Ограничения из памяти: ...
```

Несколько выполняемых задач перечисляются в первой строке через запятую. Прочие ID — ссылки и не расширяют область задания. В реализации M/L нужны и эта строка, и путь к спеке. Нельзя прикрыть черновую задачу утверждённой спекой другой задачи. Каждая самостоятельная M/L-задача имеет спеку с совпадающим ID; дочерние спеки могут ссылаться на контракт родителя.

Параллельные исполнители не делят файлы и ресурсы сборки/тестов без координации. Один координатор ведёт файл задачи. Ревьюер работает по итоговому диффу и конкретным сценариям; пожелания новой функциональности отделяются от дефектов. После трёх раундов без прогресса пересматривается подход, после пяти открытых блокирующих раундов объясняется препятствие.

Свидетельства проверки должны относиться к финальному состоянию файлов. Успешный exit code без реально выполненных проверок недостаточен. Актуальный вывод проверки можно использовать повторно; новые изменения или сомнения требуют нового прогона. Самопроверка явно называется самопроверкой. Коммит — по разрешению пользователя/политике проекта, push и публикация — по соответствующему разрешению.

## Агенты и модели

| impl-sonnet | Механические правки | sonnet | gpt-6.1-sol | high |

| review-opus | Независимое ревью | claude-opus-5-5 | gpt-6.1-sol | high |
| product-critic | Продуктовые риски | claude-opus-5-5 | gpt-6.1-sol | high |
| arch-critic | Архитектурные риски | claude-opus-5-5 | gpt-6.1-sol | high |

Это заданные профилями значения, не обещание доступности моделей в аккаунте. Названия opus/sonnet в Codex — идентификаторы ролей. При недоступной роли сообщите об этом, используйте разрешённого универсального агента с переданными правилами либо последовательную работу. Универсальный агент не получает исключения «только чтение» от хука только по тексту обещания.

## Память

Навык `workflow-memory` предоставляет индекс и семь коротких доменов: verification, data, parallel, contracts, ui, runtime, scope. Загружаются только связанные с задачей разделы. База содержит обезличенные уроки; приватные заметки и целые истории проектов в неё не скопированы.

`docs/memory/project.md` — карта действующих ограничений проекта. Новые уроки сохраняются в `docs/memory/<domain>.md`: условие → ошибка → действие → проверка, источник, дата и область применимости. Непроверенные гипотезы остаются в задачах; устаревшие записи помечаются как заменённые. Память не даёт разрешения на действия и не имеет приоритета над текущим запросом или проверенным контрактом.

## Навыки и команды

| Claude | Codex | Назначение |
| --- | --- | --- |
| /task | $task | Создать/продолжить задачу |
| /spec | $spec | Подготовить и согласовать спеку |
| /debug | $debug | Воспроизвести, найти причину, проверить исправление |
| /board | $board | Обновить доску |
| /release | $release | Подготовить CHANGELOG, предложить коммит |

```sh
node .claude/hooks/board.js --print
node .claude/hooks/spec.js new VC-001 export-csv
node .claude/hooks/spec.js check VC-001
node .claude/hooks/spec.js approve VC-001
```

Для Codex замените `.claude/hooks/` на `.codex/workflow/`. Helpers запускаются из корня; вне хуков скрипты также определяют корень по своей установке и поддерживают явный путь (board: позиционный, spec: `--root`). `approve` допустим только после реального утверждения пользователем.

## Что проверяют хуки

Оба адаптера вызывают один `workflow-policy.js`. Claude: `orchestrator-guard.js` с режимами remind/pre/stop; Codex: `guard.js`. Legacy-режимы selftest/report удалены: старые требования о квоте чтений, фоне и строках спавна больше не применяются. Проверки политики входят в `npm test`.

- Выбор задачи: `Workflow-Task: VC-NNN`, `/task VC-NNN` или `$task VC-NNN`; иначе ID из пользовательского запроса, затем активные задачи вне backlog/done. Выбор хранится отдельно по корню и session_id во временном каталоге. Прямые изменения файлов задач запоминаются для Stop.
- PreToolUse: валидная утверждённая спека для M/L; совпадение ID, запись approved, заполненные обязательные разделы. Для делегирования реализации/ревью — явный выбор задачи и путь к спеке в брифе.
- Поддерживаемые действия: apply_patch, Edit, Write, MultiEdit, NotebookEdit; Bash, PowerShell, exec_command, shell, shell_command; ввод write_stdin; Agent/Task/spawn_agent и followup_task/send_message/SendMessage. Опрос процесса и Ctrl+C разрешены.
- До апрува разрешены плановые Markdown-файлы tasks, docs/specs, docs/decisions.md, docs/memory; для apply_patch проверяются все пути, включая переименование. Переходы наружу и ссылки в пути плановых файлов отклоняются. Простые команды чтения разрешены по консервативному списку; пайпы, цепочки и неизвестные команды отклоняются. Helpers board/spec разрешены из корня.
- До спеки можно запускать explore-opus, product-critic, arch-critic, ui-designer для чтения. Продолжения агентов при черновой M/L блокируются консервативно: хук не знает, как агент интерпретирует новый бриф.
- Stop: у выбранной done-задачи проверяются отмеченные критерии и запись проверки/результата. При нехватке даётся один дополнительный ход; повторный Stop не зацикливается.

Хуки не являются границей безопасности. Они не доказывают человеческое согласие, подлинность результатов, отсутствие дефектов, соответствие каждой строки кода спеке или фактический режим чтения субагента. Неизвестные инструменты, внешняя ручная запись, отключение хуков, подмена файлов и ошибки выбора задачи не покрываются. Без задач гейт не применяется. Общая БД задач не имеет межсессионной блокировки: не ведите одну задачу одновременно в Claude и Codex. Качество обеспечивается также брифом, тестами и ревью.

Контракты событий: [Claude hooks](https://code.claude.com/docs/en/hooks), [Codex hooks](https://learn.chatgpt.com/docs/hooks). Профили: [Codex subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents).

## Разработка кита и проверки

```sh
npm test
```

Харнесс создаёт временные проекты, проверяет install/update/status/uninstall для обоих клиентов, сохранность пользовательских файлов, память, доску/спеки и отрицательные сценарии общей политики. Обработчики запускаются отдельными процессами с JSON stdin из фактических установленных определений. Эти проверки не требуют доступа к моделям; живые проверки CLI описаны отдельно в отчёте.

Роли редактируются в `kit/agents/*.md` и `kit/codex/agents/*.toml`. Общие навыки — `kit/skills/`, варианты Codex — `kit/codex/skills/`. Исходники базовой памяти — `kit/skills/workflow-memory/references/`, шаблоны пользовательских документов — `kit/templates/`. Изменения процесса должны быть согласованы между инструкциями, навыками, хуками и тестами. Версия — `VERSION` и `package.json`.
