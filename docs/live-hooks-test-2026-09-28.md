## Условия запуска и неудачные пробы

Каждый сценарий запускался отдельным `codex exec` с `--sandbox workspace-write --ephemeral --json`. Настройки доверия временного проекта передавались только через `-c`, без записи в пользовательский config.toml. Проверенные определения хуков для этого запуска разрешались флагом `--dangerously-bypass-hook-trust`; это тестовая процедура, не рекомендуемая настройка обычной работы. В обычном проекте нужно проверить определения через `/hooks`.

Первая проба с `--ignore-user-config` столкнулась с read-only режимом из-за отсутствия Windows sandbox-настройки; она не засчитана. После явного выбора Windows sandbox=elevated запись прошла без проектного хука — тоже не засчитано. Только запуск с обычными конфигурационными слоями дал подтверждённый отказ workflow-kit. Наличие пустого `.codex/config.toml` не исправляло этот эффект; итоговый shell-тест прошёл без такого файла. Не используйте `--ignore-user-config` для проверки этой интеграции на указанной версии CLI.

## Делегирование

Для проверки использовалась отдельная сохраняемая сессия `01a0e7dd-05b6-7a53-bd9d-d1341d8f2f6f`. В её локальном rollout подтверждены реальные вызовы `collaboration.spawn_agent`:

- `/root/vc001_executor`, роль worker: файл уже соответствовал утверждённой спеке, изменений не потребовалось; DONE.
- `/root/vc001_reviewer`, отдельный read-only ревьюер: самостоятельно прочитал спеку и файл, findings отсутствуют; DONE.

Модели не переопределялись. Координатор отдельно получил `export: 1 type: number`, код 0. `git rev-list --all --count` — 0. Это подтверждает механизм делегирования и раздельность ролей; качество ревью сложной реализации этим небольшим примером не оценивается.

Первый запуск с `--ephemeral` не смог создать исполнителя (`collab spawn failed: no thread with id`). Повтор без этого флага прошёл. Для теста субагентов на указанной версии CLI используйте сохраняемую сессию.

## Границы проверки

PreToolUse — защита от ошибок процесса для apply_patch, новых shell-вызовов и spawn_agent, а не изоляция вредоносного агента. Поддельное поле approved, отключение хуков, сторонние инструменты, ввод в уже запущенный shell и ручная запись файлов не предотвращаются. Stop проверяет наличие свидетельств и галочек, но не истинность описанных результатов. Статус установщика не является проверкой доверия хукам.
