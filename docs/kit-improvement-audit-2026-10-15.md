# Аудит кита 1.5 — 2026-10-15

Изменения сделаны в claude-workflow-kit. Пять проектов-источников изучались только чтением; тестовые установки создавались во временных каталогах. Цель — сохранить качество решений и проверок, уменьшив постоянный контекст и обязательные действия без полезного результата.

## Решения

| Идея | Решение и причина |
| --- | --- |
| Общая память для любого проекта | Добавлена: короткий индекс и семь доменов в workflow-memory. Урок содержит условие применимости и проверяемое действие; это не универсальная архитектурная конвенция |
| Скопировать накопленную память целиком | Отклонено: исторические заметки смешивают исправленные дефекты, локальные команды, приватные данные и устаревшие планы. Перенесены только обобщённые механизмы ошибок |
| Загружать все best practices всегда | Отклонено: обычно нужны 1–2 домена. Проектные ограничения находятся в docs/memory, а агент получает до пяти существенных ограничений в брифе |
| Всегда запускать всех критиков и исполнителей | Заменено выбором по риску: S можно сделать напрямую; для M/L сохраняются анализ, согласованная спека и независимое ревью. Отдельные критики нужны при неопределённости или архитектурном риске |
| Экономить за счёт более слабых моделей | Не применено: при исходном аудите все семь профилей Codex использовали gpt-6-sol. Последующим запросом пользователя переведены на gpt-6.1-sol с сохранением reasoning. Без сравнительной оценки качества нет основания снижать модель ревью |
| Наказывать за число чтений и форму сообщений | Убраны квоты, обязательный фон, немедленное завершение хода и точная строка объявления спавна. Они не доказывают качество и мешали полезному исследованию |
| Общие хуки для двух клиентов | Реализовано одно ядро политики с двумя адаптерами. Проверка запускается до записи/делегирования, дополнительно проверяется оформление завершения |
| Автоматически учить память по всем логам | Не добавлено: непроверенные гипотезы остаются в задачах; запись в постоянную память требует подтверждённого механизма, источника и области применимости |

Доменная база: verification, data, parallel, contracts, ui, runtime, scope. У каждого файла есть источник и дата пересмотра. Из источников не перенесены адреса серверов, рабочие данные, учётные записи, секреты или целые истории. Конкретные исторические названия стеков не объявляются текущей архитектурой проектов.

## Исправленные дефекты кита

- Прежняя проверка Claude по транскрипту заменена общей PreToolUse-политикой: блокирование реализации M/L при отсутствующей, неполной или неутверждённой спеке.
- Явная строка Workflow-Task отделяет выполняемые задачи от упоминаний связанных задач. Для реализации/ревью M/L требуется путь к спеке. Утверждение одной задачи не открывает другую черновую задачу.
- Новая задача и несколько завершённых задач сохраняются в выборе сессии до Stop. Раньше фильтрация активных задач могла потерять их после перехода в done.
- Плановые пути проверяются на выход из проекта и ссылки. Проверяется каждый путь patch, включая переименование. До утверждения запрещены ввод команд в работающий процесс и очевидные расширения команд чтения с запуском внешнего кода.
- Status обнаруживает изменённые условия/дубли/асинхронные определения управляемых хуков; update восстанавливает их, сохраняя сторонние обработчики.
- Три YAML-описания Claude-агентов содержали двоеточия без кавычек и не разбирались PyYAML. Теперь описания всех семи ролей заключены в кавычки; добавлена регрессия. Это возможная причина проблем регистрации, но связь с прежними сбоями не доказана живой сессией Claude.
- Удалена инструкция временно убирать общие изменения через git stash. Для независимой проверки используется отдельная копия/рабочее дерево.
- Шаблон процесса больше не предлагает дочерним M/L-задачам чужой ID спеки: у самостоятельной задачи собственная спека, с возможной ссылкой на общий контракт.

Для оценки стоимости нужен одинаковый набор продуктовых задач, сравнимые модели и окружение, измерение токенов/времени, дефектов и переделок. Такой A/B-эксперимент не проводился. Сейчас устранены конкретные источники лишнего контекста и запусков, но процент экономии не заявляется.

## Границы гарантии

Хук контролирует наблюдаемые поля задачи, спеки и поддерживаемые вызовы инструментов. Он не доказывает согласие человека по одной записи approved, подлинность тестового результата по тексту, качество кода или полноту ревью. Без задачи проверка не включается; неверный выбор задачи, неизвестные инструменты, ручная запись и отключение хуков не покрываются. Имена плановых ролей не доказывают фактическую работу только чтением.

Stop даёт одну дополнительную попытку оформить результат и не создаёт бесконечный цикл. Совместная запись задач разными сессиями требует координации: межсессионной блокировки нет. Не добавлялась инфраструктура тотального контроля — она не даёт обещанной гарантии отсутствия всех отклонений и увеличивает стоимость сопровождения.

Форматы событий и решений сверены с официальными справочниками [Codex hooks](https://learn.chatgpt.com/docs/hooks) и [Claude Code hooks](https://code.claude.com/docs/en/hooks). Проверка конфигурации установщиком не равна выполнению хука клиентом; доверие и разрешение хуков остаются настройками клиента.

Фактические результаты и незавершённая проверка авторизованного Claude CLI перечислены в [отчёте проверок](verification-2026-10-15.md).
